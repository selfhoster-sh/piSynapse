# piSynapse v2.0.0 — Many people, no mixing

The first release since v1.8.0 (204 commits): piSynapse grows from a
single-user home server into a multi-user household server that learns
from everyone without mixing anyone — plus a rebuilt onboarding, real
themes, and a hardened core.

## Accounts & sign-in

- **Multiple users, one server.** Register with a name and password; the
  first account becomes admin. Usernames are unique and system names
  (`admin`, …) are reserved.
- **Password login with browser sessions.** Sessions live server-side behind
  HttpOnly cookies — the API key never sits in the browser anymore.
  Per-device API keys keep working for apps, scripts, and the owner.
- **Admin panel in Settings.** Approve or revoke accounts, delete them with
  a full data wipe, and review contested routing suggestions.
- **Guided onboarding.** Gateway (sign in / register), a key ceremony that
  shows the API key exactly once (copy/download-gated), then city, mail,
  and Nextcloud steps — each skippable with honest consequence notes.

## Learning together, privately

- **Feedback with an owner.** Thumbs and corrections attach to your own rows
  only; cross-user writes fail closed.
- **Anonymous collective signal.** Corrections become normalized signatures
  (contact details masked), counted per distinct approved user. Contradictions
  freeze into the admin queue instead of entering the corpus silently.
- **Your services, your credentials.** Mail (Gmail/Proton) and Nextcloud
  accounts are stored Fernet-encrypted per user. The assistant uses yours;
  admins keep the legacy shared mailbox as fallback.

## Everyday experience

- **Settings v2.** Sidebar layout (Account, Appearance, Assistant, Voice,
  Server, Admin), live search, dirty tracking, read-only mode for
  non-admins — and real themes: Dark / Light / AMOLED plus six accents.
- **Clean URLs, no listing.** The app lives at `/static/`; directory
  enumeration returns 404 (regression-tested).
- **Know what to expect.** Tour and Settings state plainly that reply speed
  follows your hardware — a heavy first answer can take up to a minute.

## Under the hood

- Full-server audit closed out (dead code, trust boundaries, upload gates,
  write integrity, bounded summaries, stream parity) — 750-test suite,
  ruff-clean, CI green.
- SQL fully parameterized; UI output escaped with a sanitizing markdown
  pipeline; secrets masked, files locked to owner-only.
- Installer asks nothing personal anymore — accounts and services are set
  up in the browser. Fresh installs verified in a sandbox.

## Upgrading from v1.8.0

1. Pull and **restart the server** (systemd or manual) — migrations apply
   automatically (schema v22, one-time backfills included).
2. Existing single-user installs keep working: the `.env` key maps to the
   owner admin account, zero rewrites.
3. Optional fresh start: back up first (`backups/`), then wipe users and
   re-onboard from a clean browser.
4. Behind HTTPS? Set `SESSION_COOKIE_SECURE=on`. ProtonMail via Bridge
   needs a paid plan; each account is added to the Bridge once by the admin.
5. New `.env` keys are auto-generated (`MAIL_CREDS_KEY`) or defaulted
   (`SESSION_COOKIE_SECURE=off`) — reruns never wipe them.
