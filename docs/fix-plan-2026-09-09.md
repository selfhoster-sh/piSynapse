# piServe Düzeltme Planı — 2026-09-09

Kaynak: `docs/server-audit-2026-09-09.md` (106 bulgu).
İlke: **önce güvenli temizlik → izolasyon → bütünlük → boru hattı → güvenlik →
kurulum → kontrat dondurma.** Her faz kendi regresyon testiyle kapanır; testler
sona bırakılmaz. Her faz bitiminde `pytest` yeşil + ilgili acceptance kriteri
doğrulanır. Kapsam dışı: `android/`, `static/` UI (port kararına kadar donduruldu).

- Doküman düzeltmeleri (Y21): tool sayısı 27→23, OpenWeatherMap→Open-Meteo+Nominatim,

- Kabul: aynı `session_id` + farklı `user_id` ile veri/özet sızıntısı yok.

## Faz 3 — Yazma bütünlüğü (K6,Y3 + B-Y1,B-O1..O4 + ilişkili) [M]

Amaç: eşzamanlılıkta kayıp/çapraz yazma bitsin.
- `SELECT last_insert_rowid()` → `cursor.lastrowid` (2 nokta).
- `save_message` ve gruplu yazmalara kısa `BEGIN IMMEDIATE` transaksiyonu;
  FTS insert best-effort (B-Y1) + drift-rebuild'e bırak.
- Tüm çıplak `db.commit()` → `_commit_with_retry`/`_write_with_retry`.
- `save_*_map`: tek transaksiyon + sonda tek commit.
- `import_messages`: `(user_id, client_key)` için `CREATE UNIQUE INDEX`
  (migration — rebuild gerektirmez) + `ON CONFLICT DO NOTHING`
  (TOCTOU Kritiğe yükseltildi).
- İndeksler: `conversations(client_key)`, `memories(created_at)`,
  `tool_audit_log(conversation_id)`, `substr(created_at,1,10)`.
- WAL: `journal_size_limit` + periyodik `wal_checkpoint(PASSIVE)`.
- `update_session_summary`'e `last_active` + retry; title eşiği `COUNT<=2` ilk-fırsat;
  RAKE'e e-posta/URL maskesi; f-string ALTER allowlist+quoting.
- Test: migration adım testi, eski-DB testi, `BEGIN IMMEDIATE` concurrency testi,
  FTS-hata enjeksiyonunda mesaj kaybı yok testi.
- Kabul: paralel yazma testinde çapraz FTS/audit sıfır, kilitlerde 500 yok.

## Faz 4 — Özet alt-sistemi (Y1,Y2,Y4 + B-O3-ilişkili) [M]

Amaç: rolling summary'yi sınırlı + yarışsız + onarılabilir yap (port kontratının çekirdeği).
- `get_messages_to_summarize`: dönüşe `ORDER BY id ASC LIMIT ?` gerçek cap'i;
  `summarized_until` yazılan son id'ye ilerlesin (cap'li ilerleme semantiği).
- Silme/retention sonrası `summarized_until = MIN(boundary, MAX(id))` düzeltmesi
  + özet geçersiz kılma (feedback/audit cascade ile birlikte).
- `_update_summary`/`_enrich_title`: session başına `asyncio.Lock` veya koşullu
  `UPDATE ... WHERE summarized_until=?`.
- Test: DB'li boundary/ilerleme testi, cap testi (binlerce mesajda transcript
  üst sınırı), silme-sonrası-onarım testi, çift-görev yarışı testi.
- Kabul: 10 bin mesajlık session'da özetleyiciye giden transcript ≤ cap;
  silme sonrası özetleme boş dönmüyor; yarışta regresyon yok.

## Bilinen riskler

- `BEGIN IMMEDIATE` + singleton bağlantı: aiosqlite seri çalışır; kilit
  davranışını Faz 3 testleri kilitler, gerileme olursa havuza geçilir.
- `(user_id, client_key)` UNIQUE index: mevcut dublike varsa migration patlar —
  önce dublike sayımı yapan pre-check eklenecek.
- `?k=` kaldırma + CORS sıkılaştırma mevcut istemcileri etkileyebilir —
  Faz 6'da istemci (UI) uyumu doğrulanacak.
- Systemd regen canlı makinede — Faz 7 kullanıcı onaylı, yedekli.
